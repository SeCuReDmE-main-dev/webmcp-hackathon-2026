# WebMCP-QCG — feature classification

Date: 2026-08-29
Classification axis: evidence value, differentiation and seven-day delivery risk

## A. Proven foundation

These capabilities already possess local executable evidence.

| Feature | Class | Current proof | Public claim boundary |
|---|---|---|---|
| Native WebMCP registration and invocation | **PROVEN CORE** | Four tools discovered and invoked in the supported in-app browser | Proven for the recorded environment and trace |
| Deterministic five-way decision | **PROVEN CORE** | Five scenario cards return the expected bounded decision | Current cards are fixtures rather than imported scientific artifacts |
| Progressive tool availability | **PROVEN CORE** | Simulation appears only for `simulate_first` plus visible consent | One-time consent governs the local fixture |
| Bounded Q# Worker simulation | **PROVEN CORE** | 64/64 Bell shots, Bell invariant true | One pinned Bell program, local WebAssembly only |
| Evidence export and zero-call counters | **PROVEN CORE** | JSON/Markdown export, external calls `0` | Counters describe QCG's own execution path |
| Human fallback interface | **PROVEN CORE** | Page remains usable when WebMCP is unavailable | Native agent discovery still depends on a supported browser environment |

## B. Relevance threshold for the workbench

These features convert a demonstration into a tool a quantum specialist can evaluate.

| Feature | Class | Acceptance contract |
|---|---|---|
| Real artifact intake | **MUST NEXT** | Read OpenQASM 3 or Q# locally, compute a digest and keep raw code outside compact agent responses |
| Target-profile snapshot | **MUST NEXT** | Record provider, device, native gates, qubits, limits, source, retrieval time, expiry and hash |
| Exact evidence-reuse key | **MUST NEXT** | Bind artifact, observable, target/profile, shots, compiler, seed/noise assumptions and freshness |
| Known/stale/unknown resource facts | **MUST NEXT** | Preserve uncertainty; missing price or queue data never becomes a generated estimate |
| Portable canonical receipt | **MUST NEXT** | Export decision, reason codes, hashes, authority state, evidence references and call counters |
| Inspectable authority state | **MUST NEXT** | Distinguish `ready`, `consent_required`, `authorized`, `expired` and `revoked` |

## C. Valuable after the hackathon proof

| Feature | Class | Unlocking evidence |
|---|---|---|
| qBraid or Qiskit read-only profile adapter | **SHOULD LATER** | Licence, version, freshness, normalization and failure-mode tests |
| Open Quantum readiness handoff | **SHOULD LATER** | Credential-free format and explicit user-controlled transition |
| PennyLane or CUDA-Q resource adapter | **SHOULD LATER** | Bounded install/runtime cost and one real user workflow |
| Evidence registry across sessions | **SHOULD LATER** | Privacy model, retention policy and exact-match retrieval precision |
| Signed receipt | **COULD LATER** | Threat model and key custody contract |
| Team policy packs | **COULD LATER** | At least two organizations share a repeated policy need |

## D. Explicitly outside the current product

| Feature | Class | Reason |
|---|---|---|
| QPU or paid-provider submission | **CUT MVP** | Collapses readiness and authority while adding credentials and irreversible spend |
| General multi-provider execution router | **CUT PRODUCT CLAIM** | qBraid, Qiskit MCP, Open Quantum and other platforms already occupy the execution layer |
| Arbitrary user-code execution | **CUT MVP** | Expands the browser threat model and makes a seven-day proof difficult to bound |
| Universal circuit translation | **CUT PRODUCT CLAIM** | Existing compilers and conversion graphs own this domain |
| Autonomous price or queue selection | **CUT MVP** | Live commercial facts require source freshness and user policy |
| Guaranteed savings | **CUT CLAIM** | A verified baseline and repeated real workflows are required |
| “Quantum correctness” certification | **CUT CLAIM** | The current evidence proves a bounded decision path, not scientific certification |

## Classification decision

The product advances through **real input → dated profile → deterministic decision → human authority → portable receipt**. Each future engine earns entry through an adapter contract. The workbench remains coherent because execution capability grows after evidence and authority, one bounded surface at a time.
